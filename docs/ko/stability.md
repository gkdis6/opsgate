# 안정성과 호환성

[English](../stability.md)

opsgate는 아직 1.0이 아닙니다. 이 문서는 어떤 부분을 그대로 유지할 것인지, 어떤 부분이
아직 바뀔 수 있는지, 바꿀 때 어떻게 알리는지 적습니다. 아래 규칙은 1.0부터 약속이 됩니다.
그 전까지는 지금 프로젝트가 일하는 방식이고, 예외는 모두 [변경 기록](../../CHANGELOG.md)에
남깁니다.

## 유지하는 부분

핵심 흐름은 알림, 승인 카드, 패스키 승인, 복구 확인입니다. 여기에 속하는 아래 항목은
호환성을 유지합니다.

| 항목 | 범위 |
| --- | --- |
| 설정 | `opsgate.yaml`의 `mode`, `server`, `http`, `auth`, `approval`, `providers.kubernetes`, `watch` 아래 키와 기본값 |
| MCP 도구 | `k8s_*` 도구, `approval_status`, `action_link`의 이름, 인자 이름과 타입, 필요한 scope. `approval_id`로 다시 호출하는 흐름 |
| 명령줄 | `opsgate`, `opsgate watch`, `init`, `config`, `passkey`와 문서에 있는 플래그 |
| HTTP | `/mcp`, OAuth와 패스키 경로, `/approve/...`, `/approvals...`, `/healthz` |
| 링크 | `GET /approve/action/{tool}`, `/approve/options/...`. 예전 링크도 승인 요청을 엽니다. 다만 서명은 더 이상 맞지 않을 수 있습니다 |
| 형식 | 감사 로그 필드, 서명된 watch 묶음, 서명된 승인함 알림, `approval_status` 결과 |
| 상태 파일 | 한 릴리스가 쓴 파일은 이후 릴리스가 읽습니다 |

도구 결과, 승인 페이지, 알림, 로그의 문구는 사람이 읽는 글이라 어느 릴리스에서든 바뀔 수
있습니다. 문서에 숫자로 적힌 한도도 더 안전한 값이 있으면 바뀔 수 있습니다.

## 유지를 약속하지 않는 부분

아래는 실험 기능입니다. 동작하고 테스트도 있지만, 설정, 도구, 출력이 마이너 릴리스에서
바뀌거나 없어질 수 있습니다.

- analyzer(`opsgate-analyzer`). 보고서 형식과 모델 backend 포함
- 노트 provider(`providers.note`, `note_*` 도구)
- 호스트 provider(`providers.host`, `host_*` 도구)

## 유지하는 부분을 바꿀 때

1. **추가**(새 키, 도구, 인자, 필드)는 어느 마이너 릴리스에서든 들어올 수 있습니다. 클라이언트는 모르는 필드를 무시해야 합니다.
2. **삭제하거나 뜻을 바꿀 때**는 한 마이너 릴리스 전에 알립니다. 그 릴리스에서는 예전 방식이 계속 동작하고, 서버가 시작할 때 대체 방법을 알려 주는 경고를 남기며, 변경 기록의 *Deprecated*에 적습니다. 그다음 마이너 릴리스에서 없앨 수 있고, *Removed*에 적습니다.
3. **기본값을 바꿀 때**는 *Changed*에 적고, 예전 동작으로 되돌리는 설정을 함께 적습니다.
4. **보안 수정**은 예전 동작을 두면 사용자가 위험해지는 경우 기다리지 않고 호환성을 깰 수 있습니다. 변경 기록의 *Security*에 적습니다.
5. 없어졌거나 모르는 키가 든 설정 파일은 **그 키를 알려 주는 메시지와 함께 시작에 실패합니다.** 조용히 무시하지 않습니다. 대체 방법은 변경 기록에 적습니다.

1.0 전에는 2번 규칙에 예외가 있었습니다. 0.3에서 설정 키를 없앴고, 0.4에서 Dev provider를
없앴고, 0.5에서 웹 승인 기본값을 바꿨고, 0.8에서 `action_link`가 `source=ai`
링크만 만들게 바꿨습니다. 모두 변경 기록에 있습니다.

## 버전

릴리스는 시맨틱 버저닝을 따릅니다. 보안 수정은 최신 릴리스에만 넣고, 예전 0.x 릴리스에는
넣지 않습니다. 컨테이너 이미지 태그와 바이너리의 `-version` 출력으로 릴리스를 확인할 수
있습니다.
